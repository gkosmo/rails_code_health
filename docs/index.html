Why this exists

Tech debt is invisible until it isn't.

Rails codebases accumulate hotspots quietly — a fat model here, a controller with too many actions there, a migration that quietly changes production data. By the time these problems hurt, they've been hurting for a while.

Rails Code Health was inspired by CodeScene's research on code health and maintainability — research showing that a small number of files tend to drive a disproportionate share of defects and slowdowns. This gem brings that lens to Rails specifically: it understands controllers, models, views, helpers, and migrations as first-class concepts, not just as Ruby files.

The output isn't a vague grade. It's a per-file score, a category, and concrete recommendations — the kind of thing you can bring to a sprint planning meeting.

How it works

One score per file. Four clear categories.

Each file gets analyzed for Ruby-level concerns (method length, cyclomatic complexity, nesting depth) and Rails-specific concerns (action count, callback complexity, view logic, migration risk). The signals combine into a 1–10 score and one of four categories:

Healthy
score 8.0 – 10.0
Clean, conventional, low-risk. Keep doing what you're doing.
Warning
score 6.0 – 7.9
Drifting. Worth a closer look on the next pass through this file.
Alert
score 4.0 – 5.9
Pay attention. Likely concentrating risk and slowing the team down.
Critical
score 1.0 – 3.9
Prioritize. These are the files everyone is afraid to touch.
What you see

A real report, not a vibes check.

Run rails-health in your project. You get a summary, a breakdown by file type, a list of files that need attention, and a showcase of top performers — with file paths, scores, and specific reasons:

What gets checked

Ruby fundamentals plus Rails-aware heuristics.

The gem combines language-level metrics with framework-aware checks that understand how Rails apps actually break down over time.

Ruby metrics

  • Method length
  • Class length
  • Cyclomatic complexity
  • Nesting depth
  • Parameter count
  • ABC complexity

Rails-specific

  • Controllers: action count, strong params, direct model access
  • Models: association count, validations, callback complexity, fat-model detection
  • Views: logic in templates, partials over render
  • Helpers: pure-function fitness
  • Migrations: data changes, complexity, risk surface
  • Services / interactors / serializers: dependency leaks, fat-service patterns
Quickstart

Up and running in under a minute.

1

Add the gem to your Rails app's Gemfile (or install globally):

## In Gemfile
gem 'rails_code_health', group: :development

## Or globally
$ gem install rails_code_health
2

Run analysis from your project root:

$ rails-health

Or analyze a specific path, or output to JSON:

$ rails-health /path/to/rails/project
$ rails-health --format json --output report.json
3

Gate your CI on code health. --fail-under exits non-zero if the average score drops; --max-critical exits non-zero if too many files fall into the Critical category:

$ rails-health --fail-under 7.0 --max-critical 5

Drop into a GitHub Actions workflow:

## .github/workflows/code-health.yml
name: Code Health
on: [pull_request]
jobs:
  health:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ruby/setup-ruby@v1
        with: { ruby-version: '3.3' }
      - run: gem install rails_code_health
      - run: rails-health --fail-under 7.0 --max-critical 5

Full configuration options, threshold tuning, and CI integration examples live in the project README.
